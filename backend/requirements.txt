# ── Streaming call pipeline (Pipecat) ──────────────────────────────────────────
# UPDATED after reviewing Vobiz's own official reference integration
# (Vobiz-X-Pipecat repo): Vobiz publishes a maintained PyPI package,
# pipecat-vobiz, with a correct VobizFrameSerializer + parse_vobiz_start()
# helper built against pipecat-ai 1.x's current API. That replaces the
# hand-rolled serializer this app had, which — independent of any version
# pinning — sent outbound audio as {"event": "media", ...}. Vobiz's actual
# protocol expects {"event": "playAudio", ...} for outbound audio and
# {"event": "clearAudio", ...} for barge-in; "media"/"clear" are simply not
# recognized, so even a perfectly-importable old build would have connected
# successfully and then sent audio Vobiz silently ignored. Confirmed against
# pipecat-vobiz's actual source, not docs alone.

# pipecat-ai 1.x's LLMContext/LLMContextAggregatorPair API (the old

# before was removed in pipecat-ai 1.0.0) plus pipecat-vobiz's serializer.
